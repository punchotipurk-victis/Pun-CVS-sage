## Why v2
Punnatorn (14 Nov): reading a long card under the model doesn't work. Students should **see the facts beside the model** and get
the depth only when they ask. So on desktop the card becomes a **side panel ("At a glance")** to the right of the canvas, and the
full card becomes a **"Deep dive"** below it. The phone layout stays stacked for now (it gets its own redesign later, T7.4).

## Layout
| Width | Layout |
|---|---|
| ≥ 1024 px | `.viewer` (left, flexible) + side panel (right, 360–400 px, same height as the viewer, scrolls inside). A « / » button collapses the panel so the model can use the full width (remembered). Deep dive below the viewer. |

**Side panel content (top → bottom):** category · name · `core` → `stats` as 2–3 number badges → "High yield": `quick` bites,
each with its icon (where · does · supply · danger · ecg · echo · exam · key; inline SVG, colour per icon, no icon font, no CDN)
and `**bold**` rendered → "Watch out for": the first 3 `complications` as `name` + `hook` + chip → "Pearls": level switch + Quiz me
+ the first 2 pearls of the level → "Check yourself": one SAQ of the chosen level (falls back to a student SAQ) → "Deep dive ↓" button (smooth scroll).
**Empty state** (nothing selected): "Tap a structure" + the current view's Relevant list (`EXPLORE_DATA.RELEVANT_LABELS`) as chips that select it.
A part tap (`parts[].labelId`) shows the part's name + note under `core`, and the callout reads `<name> — <part name>`.

**Deep dive (below the viewer, full width):**
- Anatomy, Function, Blood supply: the `summary` line is always shown; the `detail` opens on click (`▸/▾`). Parts as chips under Anatomy.
- Neighbours: the `with` names in one line, opening to `with: why` lines.
- Where you see it: small tiles (Echo · id / 3D cut · id / ECG). A **3D cut tile is a button** that switches to that cut view.
- Complications · n: one row each = name + chip + `hook`. A click opens a two-box flow **Mechanism → What you see** (stacked on phones).
- Pearls: the level switch, then every pearl as a box with the bold `hook` and its `text` (always fully visible; no blurring).
- Check yourself · n: every `saq` as a box: level tag, question, an optional text box ("Type your answer"), a **Check** button. Check reveals the model answer `a` and the `keys` as checkboxes; ticking them shows "k / n key points". Nothing is stored or sent.
- Sources line.

## Behaviour
- **Level switch** Student / Resident / Fellow: localStorage `h3.pearlLevel` (try/catch; default student). A level with no pearls: greyed button + "Fellow pearls coming later".
- **SAQs** (replaced "Quiz me" on 14 Nov): see Deep dive above. The text box and ticks reset when another structure is selected.
- **Bite → model:** hovering (desktop) or long-pressing (touch) a bite with `focus` highlights those tap ids on the model (the same look as the selection highlight, but without changing the selection or the callout); leaving restores. Ids may be phantom labels, landmarks, `artery:`/`vein:`/`conduction:` ids. If an id is not visible in the current view, do nothing (no camera move).
- **Chips:** scenario in `CONTENT.SC` / `SIMC.EXTRA` / `SIMC.MIS` → "Run ▸" link to `#pathology` with that scenario (pagelinks.js); `planned:<id>` → greyed, not clickable, tooltip "Coming with the Pathology simulator"; `null` → none.
- **Fallback:** tap ids with no card keep today's behaviour (`D.CARD` / `C.STRUCT` / `SIMC.VALVENOTE` / `D.NOTE` / `D.LEAFLET`), shown in the same panel (name + text only). Batches land one at a time.
- The panel never covers the canvas; the label layout (`explore-ui.js`) must use the narrower viewer width (re-run its layout on resize/collapse).

## Validator (`tools/validate_structures.py`)
- schema (jsonschema if installed, otherwise a built-in check of required fields, types and max lengths)
- unique card ids; every tap id (`labelIds`, `parts[].labelId`) in exactly one card; every tap id and every `focus` id exists (phantom LABELS, `heart-landmarks.json`, heart-mesh arteries/veins, conduction pick taps, the extra ids `explore-data.js` uses: `mitral_valve`, `fossa_ovalis`, …)
- `seenOn.echo` ids in `echo-sim/data/views.json`; `seenOn.cut` ids in `CUTS`; scenario ids exist or start with `planned:`
- prints `N card(s), M tap id(s), 0 error(s)`; also a **coverage line** (tap ids on the model with a card / without), informative only

## Acceptance
- Desktop 1280 × 800: tapping `av_node`, `MV_PML` and `artery:LAD` fills the side panel (MV_PML shows the posterior-leaflet part); the canvas keeps ≥ 60 % of the width; no panel scroll needed to see stats + bites at 800 px height.
- Hovering the AV-node "where" bite highlights Koch's triangle and the AV node; leaving clears it; the selection is unchanged.
- The level switch survives a reload; Check on an SAQ reveals the answer and key points, ticking updates the count; Fellow button greyed on a card with no fellow pearls; `planned:` chip not clickable.
- Deep dive: summaries visible, details open on click; a complication opens its flow; the `raOpen` tile switches to that cut.
- Phone 400 px: stacked, glance first, no sideways scroll.
- Validator 0 errors; screenshots desktop (panel open and collapsed) + phone; `test_heart3d.py` + `test_site.py` 0 failures; frame interval not worse than before (B6 rule).
