## 1. The data in one page

`structures.json` = `{ meta, cards: [55 cards] }`. Each card (see the schema for limits):

| Field | Use in the UI |
|---|---|
| `id`, `name`, `category`, `layer` | panel header (category = small eyebrow) |
| `labelIds[]` | **tap ids** that open this card (phantom labels like `LA`, landmarks like `koch_triangle`, `artery:LAD`, `vein:GCV`, `conduction:his`) |
| `parts[] {labelId?, name, note}` | a tap on a part's `labelId` opens the parent card and shows the part (name + note) under `core`. `labelId: null` parts are shown only in the deep dive |
| `core` | one-line summary under the name |
| `stats[] {value, label}` | 2–3 number badges |
| `quick[] {icon, text, focus?}` | 3–5 "High yield" bites; `icon` ∈ where · does · supply · danger · ecg · echo · exam · key; `focus` = tap ids to light up (session 2) |
| `anatomy`, `function`, `supply` `{summary, detail}` | deep dive sections (session 2) |
| `relations[] {with, why, focus?}` | "Neighbours" (session 2) |
| `seenOn {echo[], cut[], ecg[]}` items `{id?, text}` | "Where you see it" tiles (session 2); `cut` ids are keys of `CUTS` |
| `complications[] {name, hook, mechanism, presentation, scenario}` | panel: first 3 as name + hook + chip; deep dive: all, with the Mechanism → What you see flow |
| `pearls {student[], resident[], fellow[]}` items `{hook, text}` | panel: first 2 of the chosen level; deep dive: all |
| `saq[] {level, q, a, keys[]}` | panel: one SAQ; deep dive: all |
| `sources[]` | deep dive footer line |
| `verify[]`, `review` | **not shown** to students |

**Scenario chips.** `scenario` is one of:
- a key that exists in `C.SC` (content.js), `SIMC.EXTRA` or `SIMC.MIS` (patho-content.js) → a "Run ▸" chip that opens `#pathology` with that scenario (reuse `goSim()` / `chips()` in explore.js)
- `"planned:<id>"` → greyed chip, not clickable, tooltip "Coming with the Pathology simulator"
- `null` → no chip

Every tap id on the model now has exactly one card. The fallback (old `card()` text) stays only as a safety net.

## 3. Session 1: T7.1a data + validator, T7.1b side panel

**Goal:** on a desktop, tapping `av_node`, `MV_PML` or `artery:LAD` fills a side panel to the right of the model with the card summary. Nothing below the model changes yet.

### T7.1a data + validator
Files: `src/index.html` (one marker), `src/parts/scripts-explore.html`, new `src/js/cards-data.js`, new `tools/validate_structures.py`, `tools/test_heart3d.py`.

1. In `src/index.html` add `<!--@JSON:h3cards:data/structures.json-->` before the scripts include. Check the standalone build too.
2. New `src/js/cards-data.js` → `window.H3CARDS`:
   - `byTap(id)` → `{card, part}` or `null` (`part` is the matching `parts[]` item when `id` is a part's `labelId`)
   - `scenario(key)` → `{state: "run" | "planned" | "none", key, name}` (name from `C.SC` / `SIMC.EXTRA` / `SIMC.MIS`; planned → the id after `planned:`)
   - `all` (the card array), `level()` / `setLevel(l)` for `localStorage["h3.pearlLevel"]` (try/catch; default `"student"`)
   - Build the tap map once at load. Fail soft: if the JSON is missing, `byTap` returns `null` and the old card shows.
3. New `tools/validate_structures.py` exactly as `T7.1-PLAN.md` "Validator" says (schema via `jsonschema` if installed, else built-in checks; unique ids; every tap id in exactly one card and real; `focus` ids real; echo/cut ids real; scenarios real or `planned:`). Print `N card(s), M tap id(s), 0 error(s)` and the coverage line. Exit code 1 on errors.
4. `test_heart3d.py`: run the validator (subprocess) and `check` its exit code; check `H3CARDS.byTap("MV_PML").part.name` is non-empty in the page.

### T7.1b side panel
Files: new `src/js/cards-panel.js`, `src/style.css` (new `.x3-panel` block + the `.model-workspace` breakpoints only), `src/index.html` (panel markup if needed), **one call** in `explore.js` `select()`.

1. **Layout** (replace the 1700 px rule):
   - ≥ 1024 px: grid `minmax(0,1fr) clamp(360px, 28vw, 400px)`; panel same height as the viewer, scrolls inside, sticky.
   - 760–1023 px: panel 320 px; stats wrap 2 per row.
   - < 760 px: stacked as today (panel under the model), no sideways scroll at 400 px.
   - A **«/»** button on the panel edge collapses it to a thin strip so the viewer takes the full width; remember in `localStorage["h3.panelOpen"]`. After collapse/expand and on resize, re-run the label layout (call the existing resize path so `explore-ui.js` recomputes callouts).
2. **Content** (top → bottom), from `T7.1-PLAN.md`:
   eyebrow `category` · `name` · `core` → (part tapped: part name + note in a tinted box) → `stats` badges → **High yield**: `quick` bites with inline SVG icon per `icon` (8 small icons, one colour each, defined once in `cards-panel.js`) and `**bold**` rendered → **Watch out for**: first 3 complications as name + hook + scenario chip → **Pearls**: Student / Resident / Fellow switch + first 2 pearls of that level (a level with no pearls: greyed button, tooltip "Fellow pearls coming later") → **Check yourself**: one SAQ of the chosen level (else the first student SAQ): question, optional text box, **Check** button → reveals `a` and `keys` as checkboxes with "k / n key points" → **Deep dive ↓** button (session 1: hidden or disabled; session 2 wires it).
3. **Empty state** (no selection, and after a view change): "Tap a structure" + the current view's Relevant labels as chips; a chip selects that id (call the same path a tap uses).
4. **Hook-up:** in `select(id, hit)`, if `H3CARDS.byTap(id)` returns a card, render the glance panel instead of `card(id, hit)`; otherwise keep today's `card()` output (fallback). Keep `window.__lastCard` = the card's `name` so old tests still work.
5. **Callout text for parts:** when a part is tapped, the callout reads `<card name> — <part name>` (decision 18 in STATUS: a valve tap must name the leaflet). If this needs `explore-ui.js`, do it there with the smallest change.
6. New hooks: `EXPLORE_APP.select(id)` (if not present), `EXPLORE_APP.panel()` → `{open, cardId, partName, level, sections: [...]}`.
